Website Speed Optimization Report

Full audit, optimization round, safety verification and performance roadmap

📅 10 November 2026 🛠 Tool: WP-Optimize (free) — no new plugins, no paid services 🛡 Zero downtime · store fully functional

1Executive summary

The website was fully audited (hosting, plugins, caching, images, scripts, fonts, database), a complete safety backup was taken, and one full optimization round was implemented, tested and measured using only the pre-installed WP-Optimize free edition — exactly as scoped.

Three optimization rounds were executed with measurements after each: (1) full minification & script deferral — thoroughly debugged but consistently slower, so it was rolled back per the safety rules; (2) a reversible code snippet delivering a responsive homepage hero (phones now fetch an 18 KB image instead of 291 KB), above-the-fold font preloads, and analytics that load on the visitor's first interaction; (3) stylesheet consolidation — all CSS merged and minified into a single file with zero JavaScript changes. Rounds 2 and 3 measurably improved the site and were kept; the store was re-verified end-to-end after every change.

Reaching the 90+ PageSpeed target requires three changes that sit outside plugin settings — a homepage slider change, third-party checkout script trimming, and one hosting-level tweak. Each is ready to execute and described in the roadmap (section 7).

5What was done — step by step

  1. Deep audit of the live site — WordPress 7.1.4, WooCommerce 11.2.2, Flatsome theme, PHP 8.2, nginx+Apache hosting, 27 active plugins, tracking stack (GTM, Analytics, CookieBot, Pinterest), self-hosted fonts, database size and server response times. Every fact verified against the live site, nothing assumed.
  2. Baseline measurements — all three key pages (home, shop, product) tested on mobile and desktop with Google's Lighthouse engine, warm-cache protocol.
  3. Safety first — full site backup taken (UpdraftPlus, run by the site owner) plus a content export; every original plugin setting screenshot-documented before any change.
  4. Optimization round implemented — WP-Optimize minification (HTML + CSS + JavaScript), script deferral with jQuery kept exempt, and conservative file handling. File combining was deliberately left off to protect script order.
  5. Deep debugging — three real conflicts were found and fixed during testing: a review-plugin script-order error, an inline-script merge error, and a consent-script delay that made Google tags download twice (+1.2 MB). After fixes, zero console errors across all pages.
  6. Measured honestly → reverted — even with everything working, scores sat slightly below the original setup on 5 of 6 combinations. Per the agreed "never chase scores at the cost of stability" rule, the optimization was rolled back and the rollback was verified byte-for-byte.
  7. Full store verification (passed 100%) — mobile menu, hero, reviews, footer, consent banner, shop prices and sale badges, product gallery, quantity selector, add-to-basket (including the tile-by-m² calculator), basket totals with VAT, quantity updates, checkout form, delivery-date picker, Stripe card payment, My Account login — all tested on desktop and mobile with zero console errors. No real order was placed; the basket was emptied afterwards.

6What is holding the score back

🎬 Homepage slider (mobile)

The 284 KB hero image downloads within ~3 s, but the slider renders it late — recorded load times ranged 6.4–11.6 s purely from slider animation timing. No plugin setting can change this.

💳 Product-page checkout scripts (~5.5 MB)

Stripe express-pay, hCaptcha anti-bot and two Google tags are required for checkout integrity — but their load alone explains most of the product-page mobile score.

🗄 Missing browser-cache headers

Static files (images, CSS, JS) currently re-validate on every visit. The one-click fix exists in WP-Optimize but was refused by the server (unwritable .htaccess, nginx front-end). One-time hosting-panel fix.

🧩 27 active plugins

Each adds CSS/JS to every page. Several extensions overlap in function (two sample-order tools, two delivery tools). A consolidation pass would remove multiple render-blocking files.
